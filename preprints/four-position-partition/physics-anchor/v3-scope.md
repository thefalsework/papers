## 1. The question v3 is asking

§4.5 of `physics-anchor/feasibility.md` left an explicit open question:

> What is the natural kernel `a ∈ Sub_cl(Σ_A)` for a non-commutative `A` such that `a`'s non-regularity comes out as a witness to non-commutativity, not to shape?

The v2 run established that non-vacuity of the four-position partition on `Sub_cl(Σ)` holds for context categories built over *commutative* algebras (`C^4` for P1, `C^3` for P2), provided the context category has at least one context `V` with `m_V` non-singleton. So non-vacuity itself is shape-driven and does not distinguish quantum from classical.

The v3 question is whether — for context categories *of the same poset shape* — the partition's behaviour at *Bohrification-native kernel choices* (built from projection daseinisations or related topos-QM constructs) differs between non-commutative `A` and commutative `A_control`. If yes, the framework's machinery picks up a quantum-specific signal at the kernel level even when shape-level non-vacuity holds in both cases. If no, the partition's signal on `Sub_cl(Σ)` is shape-driven all the way down and the physics-anchor claim needs reformulation.

This is an exploratory test. The doc below scopes the test architecture; it does *not* commit to a specific quantum-signal-bearing kernel, because pre-script reasoning (see §4 below) suggests the obvious candidates may all fail in the discretisation we have to use. The script's job is to enumerate kernel candidates and observe what they produce.

---

## 2. What v3 is *not* asking

For sharpness:

- v3 is not asking whether `Sub_cl(Σ)` is non-Boolean for non-commutative `A`. It is, by HLS 2009; this is established background.
- v3 is not asking whether some kernel admits a non-vacuous partition. v2 settled this affirmatively.
- v3 is not constructing the full Bohrification topos `T(A) = [V(A), Set]` for any `A`. The full construction is multi-month formalisation work. v3 restricts to a finite discretised sub-poset `V_d(A) ⊂ V(A)` chosen to expose Bohrification-relevant structure.
- v3 is not building a daseinisation primitive from `Mathlib`/`Lean`. The daseinisation calculations are done by hand in Wolfram code from explicit linear-algebraic data.

What v3 is asking, narrowly: *given* a shape-matched pair of context categories (one over `M_2(C) ⊕ C`, one over a commutative algebra), and *given* a small library of Bohrification-native kernel candidates, does the partition behaviour at corresponding kernels differ in a way attributable to the non-commutativity of `M_2(C) ⊕ C`?

## 3. The discretised context categories

### 3.1 `V_d(M_2(C) ⊕ C)`: 8 contexts

Choose three "stabilizer" MASAs of `M_2(C)` — generated by the Pauli projections `P_Z = |0⟩⟨0|`, `P_X = |+⟩⟨+|`, `P_Y = |+i⟩⟨+i|` — plus the central projection `e = (0, 1)` for the `C` summand:

| Context  | Generators                                                | Dimension | Underlying projections                  |
|----------|-----------------------------------------------------------|-----------|-----------------------------------------|
| `V_0`    | `⟨1⟩` where `1 = (I_2, 1)`                                | 1         | `{0, 1}`                                |
| `V_Z`    | `⟨1, (P_Z, 0)⟩`                                           | 2         | `{0, (P_Z, 0), (I_2 - P_Z, 0), 1}`       |
| `V_X`    | `⟨1, (P_X, 0)⟩`                                           | 2         | analogous                               |
| `V_Y`    | `⟨1, (P_Y, 0)⟩`                                           | 2         | analogous                               |
| `V_C`    | `⟨1, (0, 1)⟩`                                             | 2         | `{0, (I_2, 0), (0, 1), 1}`              |
| `V_top_Z`| `⟨1, (P_Z, 0), (0, 1)⟩`                                   | 3         | sums of `{e_1, e_2, e_3} := {(|1⟩⟨1|, 0), (|0⟩⟨0|, 0), (0, 1)}` |
| `V_top_X`| `⟨1, (P_X, 0), (0, 1)⟩`                                   | 3         | sums of `{f_1, f_2, f_3} := {(|+⟩⟨+|, 0), (|-⟩⟨-|, 0), (0, 1)}` |
| `V_top_Y`| `⟨1, (P_Y, 0), (0, 1)⟩`                                   | 3         | sums of `{g_1, g_2, g_3}` analogous     |

Hasse diagram (covers):
- `V_0` is covered by `V_Z, V_X, V_Y, V_C`.
- `V_Z` and `V_C` are each covered by `V_top_Z` only.
- `V_X` and `V_C` are each covered by `V_top_X` only.
- `V_Y` and `V_C` are each covered by `V_top_Y` only.

So `m_{V_top_Z} = {V_Z, V_C}`, `m_{V_top_X} = {V_X, V_C}`, `m_{V_top_Y} = {V_Y, V_C}`. Each maximal context has two distinct minimal sub-contexts — the structural prerequisite v2 identified as required for non-trivial stagewise Heyting NOT.

Spectra (with explicit characters):
- `Σ(V_0) = {*}`.
- `Σ(V_Z) = {0_Z, 1_Z}`, where `0_Z` sends `(P_Z, 0) → 0` and `1_Z` sends `(P_Z, 0) → 1`. (Analogous for `V_X, V_Y`.)
- `Σ(V_C) = {0_C, 1_C}`, where `0_C` sends `(I_2, 0) → 1`, `(0, 1) → 0` (the "M_2 side"); `1_C` sends `(0, 1) → 1` (the "C side").
- `Σ(V_top_Z) = {λ_1, λ_2, λ_3}` corresponding to the three minimal projections `e_1, e_2, e_3`. (Analogous for `V_top_X, V_top_Y`.)

Restriction maps: derived from inclusion of subalgebras. For instance `V_top_Z → V_Z`: `λ_1 → 0_Z, λ_2 → 1_Z, λ_3 → 0_Z`. `V_top_Z → V_C`: `λ_1 → 0_C, λ_2 → 0_C, λ_3 → 1_C`. Other restrictions analogous.

This 8-context discretisation is a finite faithful sub-poset of `V(M_2(C) ⊕ C)`. The continuum-of-MASAs structure of `V(M_2(C))` is approximated by three antipodal directions on the Bloch sphere. The discretisation discards the curvature of the MASA-continuum but preserves the *incomparability* of distinct stabilizer MASAs, which is the Kochen-Specker-relevant feature.

### 3.2 Poset-isomorphic commutative control

The control algebra is `A_control = C^7`, embedded so that `V_d(A_control)` has the same 8-context Hasse structure as `V_d(M_2(C) ⊕ C)`. Concretely:

Pick mutually orthogonal central projections `p_1, p_2, ..., p_7` in `C^7` with `p_1 + ... + p_7 = 1`. Define:
- `q_Z := p_1 + p_2`, `q_X := p_3 + p_4`, `q_Y := p_5 + p_6`, `q_C := p_7`.
- `V'_0 := C·1`.
- `V'_Z := ⟨1, q_Z⟩`, `V'_X := ⟨1, q_X⟩`, `V'_Y := ⟨1, q_Y⟩`, `V'_C := ⟨1, q_C⟩`.
- `V'_top_Z := ⟨1, q_Z, q_C⟩`, `V'_top_X := ⟨1, q_X, q_C⟩`, `V'_top_Y := ⟨1, q_Y, q_C⟩`.

The Hasse structure of `V'_d(C^7)` matches `V_d(M_2(C) ⊕ C)` exactly. Spectra sizes also match: `|Σ(V'_0)| = 1`, `|Σ(V'_*)| = 2` for the sub-MASAs, `|Σ(V'_top_*)| = 3` for the maximal contexts. Restriction maps are determined by inclusion and behave analogously.

The crucial difference: in `C^7`, the maximal contexts `V'_top_Z, V'_top_X, V'_top_Y` are *not* MASAs of `C^7` (`C^7` itself is the unique MASA). They are *sub*-MASAs. So `V'_d(C^7)` is a chosen sub-poset of `V(C^7)`, not the full poset.

This is fine for the test. The goal is to compare `Sub_cl(Σ)` over two *poset-isomorphic* context categories where one carries non-commutativity in the underlying algebra and the other does not. Both `Sub_cl(Σ)` lattices will be of similar size; differences must come from how the spectra/restriction-maps interact with daseinisation-derived kernels, not from poset shape.

### 3.4 Dimensionality caveat (read before running)

`M_2(C)` has dimension 2, which is below the Kochen-Specker threshold (`dim ≥ 3`). The spectral presheaf `Σ_{M_2(C)}` has global sections; the KS obstruction does not bite for `M_2(C)` alone. Adding the `C` summand to give `M_2(C) ⊕ C` raises the total dimension to 5, but the *non-commutative part* remains `M_2(C)` and the KS-relevant obstruction does not appear in `V(M_2(C) ⊕ C)`.

Practical implication: any v3 candidate whose intended signal is "the Kochen-Specker gap manifests as a non-tight subobject in `Sub_cl(Σ)`" is *structurally pre-disposed to a negative or mixed result* on the `M_2(C) ⊕ C` discretisation, because the gap that would carry the signal doesn't exist at this dimension.

What this means for the v3 test:
- A *negative result* on `M_2(C) ⊕ C` is the expected outcome for the cell-non-emptiness criterion, and would be informative about the dimensionality threshold rather than about the framework's machinery.
- A *positive result* would be a surprise and would need careful diagnostic (is the signal coming from non-commutativity, from spectrum-size arithmetic at the off-direction contexts, or from a discretisation artefact?).
- A *mixed result* (cell cardinalities differ but cell non-emptiness doesn't) is also expected; it tells us the framework's machinery is sensitive to algebra-structural divergences at the daseinisation-lift level even when the categorical structure of the partition is invariant.

The right next move after a negative or mixed v3 result is to scale to `M_3(C)` (smallest matrix algebra carrying KS). The v3 script architecture (§6) is written to be parameterised over the algebra so the `M_3(C)` extension is a swap of the projection-arithmetic primitives plus a richer discretisation of `V(M_3(C))`, not a rewrite. v3 on `M_2(C) ⊕ C` is therefore best understood as a *sanity-check and instrumentation* run: it confirms the script architecture works end-to-end, establishes the cell-cardinality baseline, and produces a target for v4 (or v3.1) on `M_3(C)`.

A pre-script hand calculation in the conversation that produced this scope walked through §4.1 through §4.6 on the 8-context discretisation and confirmed: §4.1 (`δ(P)`), §4.3 (`δ(P) ∧ δ(¬P)`), §4.4 (anti-daseinisation) are all tight and therefore Heyting-regular (Exploitation = ∅); §4.2 (`δ(P) ∨ δ(¬P)`) = ⊤ (trivial kernel); §4.5 (`δ(P) ∧ ¬δ(¬P)`) collapses to the same component pattern `{V_0, V_Z}` in both quantum and classical (no cell-non-emptiness divergence); §4.6 (`¬(δ(P) ∨ δ(¬P)) = ⊥`) is bottom and the partition is trivial. So the cell-non-emptiness criterion is *expected* to come back negative on candidates 4.1–4.6 in this discretisation, with cell cardinalities expected to differ between quantum and classical at §4.1 and §4.3. The §4.7 exhaustive sweep and the §4.8 Heyting-implication kernel are the candidates with unknown pre-script verdicts; the script's value is partly in running these and partly in confirming the predictions on §4.1–§4.6.

### 3.3 Quantum projection and its classical analogue

In `M_2(C) ⊕ C`: take `P := (P_Z, 0)` as the "quantum" projection. `P` lives in `V_Z` and `V_top_Z`; it does *not* lie in any other context of the discretisation (because `P_Z` does not commute with `P_X` or `P_Y`).

In `C^7`: take `P' := q_Z = p_1 + p_2` as the "classical analogue." `P'` lives in `V'_Z`, `V'_top_Z`, and also in `V'_top_X, V'_top_Y` if those contained `q_Z` — but they don't. They contain `q_X, q_Y` respectively. So `P'` is in `V'_Z` and `V'_top_Z` only — same containment pattern as `P` in the quantum side.

This is the per-context match the comparison needs: `P` and `P'` are each "directional projections" that sit in their own MASA only. Any divergence between the quantum and classical sides comes from the *daseinisation lifts at non-containing contexts*, not from the containment pattern itself.

For the quantum side, `δ^o_{V_X}(P)` is computed via "smallest projection in `V_X` ≥ `P`." The projections of `V_X` are `{0, (P_X, 0), (I_2 - P_X, 0), 1}`. Since `P_Z` and `P_X` don't commute, neither `(P_X, 0)` nor `(I_2 - P_X, 0)` dominates `(P_Z, 0)` (positive-semidefinite ordering); the smallest dominator is `1`. So `δ^o_{V_X}(P) = 1`.

For the classical side, `δ^o_{V'_X}(P')`: projections of `V'_X` are `{0, q_X, 1 - q_X, 1}`. We need smallest ≥ `q_Z = p_1 + p_2`. `q_X = p_3 + p_4` is orthogonal to `q_Z`, so does not dominate. `1 - q_X = p_1 + p_2 + p_5 + p_6 + p_7` does dominate `q_Z`. So `δ^o_{V'_X}(P') = 1 - q_X`.

**This is the first concrete divergence.** In the quantum case `δ^o_{V_X}(P) = 1` (full identity); in the classical case `δ^o_{V'_X}(P') = 1 - q_X` (a proper sub-identity projection). The non-commutativity of `M_2(C)` forces the daseinisation to "round up to the identity" at `V_X`, whereas the commutative `C^7` allows a finer lift.

This divergence at the daseinisation level is what any v3 kernel built from `δ(P)` will inherit. Whether it propagates to a partition-cell divergence is what the script tests.

## 4. Kernel candidates to enumerate

I want to be honest that pre-script reasoning (worked partially in the conversation with the assistant on 2026-05-26) suggested that the most obvious candidate — `δ(P) ∨ δ(¬P)` — may collapse to the top subobject in this discretisation. So v3 enumerates several kernel candidates rather than committing to one in advance. The script tabulates the partition cells at each candidate for both the quantum and classical sides; the comparison is column-wise across the two tables.

### 4.1 Single daseinisation

`a := δ(P)`. Døring 2012 Prop. 5 + Cor. 2 says `δ(P)` is Heyting-regular (it is tight), so `Exploitation = ∅` at this kernel structurally. The interesting comparison is Distribution-cell *count* — how many subobjects straddle `δ(P)` and `¬δ(P)` — and whether this count differs between quantum and classical.

Expected: structurally similar between quantum and classical at the cell-non-emptiness level (both have empty Exploitation); possibly different at the cell-count level.

### 4.2 Join of daseinisation pair

`a := δ(P) ∨ δ(¬P)`. Pre-script worked example for the 8-context discretisation gives `δ(P) ∨ δ(¬P) = ⊤` in the quantum case, which would be Heyting-regular trivially. If this generalises, the join kernel does not work as a quantum-signal locus in this discretisation.

Test it anyway because the worked example used naive `δ^o_V(¬P)` and might have missed a subtlety. The script confirms or denies.

### 4.3 Meet of daseinisation pair

`a := δ(P) ∧ δ(¬P)`. The meet of two tight subobjects is tight (this is the easier direction in Døring's characterisation), so this is also Heyting-regular and `Exploitation = ∅` structurally.

Same caveat as 4.1: interesting at the cell-count level if at all.

### 4.4 Anti-daseinisation (inner-daseinisation-derived)

Døring distinguishes outer daseinisation `δ^o_V(P)` (smallest in `V` majorising `P`) from inner daseinisation `δ^i_V(P)` (largest in `V` majorised by `P`). The "anti-daseinisation" subobject built from `δ^i` is dual to `δ`; it's also tight (per Døring 2012 Prop. 6) and therefore regular.

So as a single kernel this is structurally analogous to 4.1.

**Post-run correction (2026-05-26).** The naive construction "anti-daseinisation_V = `{λ ∈ Σ(V) : λ(δ^i_V(P)) = 1}`" does *not* produce a valid clopen subobject in our convention (which has `restrict(S_V') ⊆ S_V` for `V ≤ V'`). Reason: inner daseinisation is monotone increasing (`V ≤ V'` ⇒ `δ^i_V(P) ≤ δ^i_{V'}(P)`), so a character of `V'` evaluating `δ^i_{V'}(P)` to 1 can restrict to a character of `V` evaluating `δ^i_V(P)` to 0. The v3.wl script's `antiDaseinQ` / `antiDaseinC` functions produce such an invalid subobject (concretely: the `V_0` component is empty while the `V_Z` component is non-empty), and the four-cell counts the script reported for §4.4 are on an inconsistent input. They are not substantive.

The Heyting-correct anti-daseinisation in our convention is `¬δ(¬P)` (Heyting complement of the daseinisation of the projection complement), which is computed correctly inside candidate 4.5. Future runs should drop §4.4 entirely or replace it with `¬δ(¬P)` as a standalone kernel, but since 4.5 already wraps `¬δ(¬P)` inside a meet with `δ(P)`, the structural content is preserved.

### 4.5 Difference subobject `δ(P) ∧ ¬δ(¬P)`

`a := δ(P) ∧ ¬δ(¬P)`, where `¬δ(¬P)` is the Heyting complement of `δ(¬P)` (computed via Døring Prop. 2 stagewise NOT). This subobject is the "definitely-`P`, also-not-definitely-not-`P`" region.

For classical `A`, `δ(P) ∧ ¬δ(¬P)` should coincide with `δ(P)` (since `δ(P) ∧ δ(¬P) = δ(0) = ⊥`, so `δ(P) ≤ ¬δ(¬P)`).

For quantum `A`, this can be a proper subobject of `δ(P)` because of the Kochen-Specker gap.

This is the candidate I'm now most hopeful about. If `δ(P) ∧ ¬δ(¬P) ≠ δ(P)` in the quantum case but `=` in the classical case, then the kernel divergence is a clean quantum-specific signal *and* this kernel candidate is plausibly non-regular (it's the meet of a tight and a regular-non-tight, which need not be tight).

### 4.6 Non-daseinisation kernel from the Kochen-Specker gap

Define `KS_gap := ⊤ \ (δ(P) ∨ δ(¬P))` heuristically — although this isn't directly a subobject of `Σ` (subobject lattices don't admit set-theoretic complement), there's a topos-internal version: the subobject `KS := ¬(δ(P) ∨ δ(¬P))`. For classical `A` this should be `⊥`; for quantum `A` with Kochen-Specker projections, this can be non-trivial. Then kernel `a := KS` itself.

If `KS = ⊥` in the discretisation we have (per pre-script computation), this kernel collapses to bottom and the partition is trivial — but the very fact that `KS = ⊥` for our 8-context discretisation of `M_2(C) ⊕ C` would itself be a structural finding: it tells us the discretisation is too coarse to surface the gap at the Sub_cl level.

### 4.7 Exhaustive enumeration over non-regular kernels

As a backstop: enumerate *all* non-regular subobjects of `Sub_cl(Σ)` for both the quantum and classical sides. Compute partition counts at each. Look for kernels where the partition cell counts differ across sides.

This is what the script ends with if 4.1–4.6 are all inconclusive. It's an "exploratory data analysis" pass — if non-trivial differences exist, they'll show up in some kernel; what we learn is which kernels carry the differences, even if we can't name them in advance with a Bohrification recipe.

### 4.8 Heyting implication kernel

`a := δ(P) → δ(¬P)` (Heyting implication in `Sub_cl(Σ)`, computed stagewise via the standard formula `(s → t)_V = ⋂_{V' ≥ V} {λ ∈ Σ(V) : λ|_{V'} ∈ s_{V'} ⇒ λ|_{V'} ∈ t_{V'}}`, or equivalently as the largest `x` with `x ∧ δ(P) ≤ δ(¬P)`).

The Heyting implication is less directly studied in topos QM than the daseinisation pair itself, but it's a natural construct because `δ(P) → δ(¬P)` reads as "if `P` is definite then `¬P` is definite" — which is *vacuously true* classically (a state in which `P = 1` is one in which `¬P = 0`, so `¬P` is also definite, namely with value 0) but carries the Kochen-Specker gap quantum-mechanically: the implication can fail at contexts where neither `P` nor `¬P` has a definite-projection value.

Pre-script status: not hand-computed in the scoping conversation. The script computes it on both sides; the candidate is included precisely because its pre-script verdict is uncertain.

This candidate is included on the user's explicit request after reviewing the §4.1–§4.7 hand-calculation outcomes.

## 5. Comparison criteria

The script tabulates, for each kernel candidate `a` from §4, on both the quantum and classical sides:

- `|Sub_cl(Σ)|` and number of non-regular subobjects.
- At `a`: is it Heyting-regular? Are the four cells `(I, R, E, D)` non-empty? What are their cardinalities?
- For the daseinisation-derived kernels, side-by-side: `δ(P)_V` vs `δ(P')_V` at each `V` (and similarly for `¬δ(¬P)`, etc.). Identify the *first context* where the lifts differ.

A *positive v3 result* (quantum signal found) requires at least one kernel candidate `a` such that:
- the four-cell pattern differs between quantum and classical at the *cell-non-emptiness* level (not merely at cell-cardinality), AND
- the divergence is traceable to the daseinisation lift at a non-containing context (§3.3 calculation), so it's attributable to non-commutativity rather than to incidental poset arithmetic.

A *negative v3 result* (quantum signal not found) is: all kernel candidates produce structurally identical four-cell patterns between the quantum and classical sides, with at most cell-cardinality differences attributable to spectrum-size arithmetic.

A *third outcome* worth flagging: cell-cardinality differs systematically across sides for many kernels, but no kernel produces a cell-non-emptiness divergence. This would mean the framework detects a quantum/classical difference but only quantitatively, not categorically. This is interesting but weaker than a positive result.

## 6. Script architecture

`wolfram/physics-anchor/four-position-physics-v3.wl`. Sections:

1. **Generic machinery** (copied from v2 with `liftProj` identity-lift fix): `subobjectsOf`, `heytingNot`, `regularQ`, `meetSub`, `joinSub`, `subEqQ`, `leqSub`, `bottomSub`, `topSub`. Add `joinSub` (componentwise union, then re-validate compatibility, then take the smallest valid subobject containing it).

2. **Linear-algebraic primitive**: explicit `M_2(C)`-style projection arithmetic. Represent projections in `M_2(C)` as 2×2 matrices; in `M_2(C) ⊕ C` as pairs `(M, scalar)`. Define `dominatesQ[P, Q]` as `M_2(C) ⊕ C`-positive-semidefiniteness check (`P - Q` has non-negative eigenvalues). Define `projectionsIn[V]` as the explicit list of projections in each context.

3. **Daseinisation primitive**: `daseinO[V, P] := MinBy[Select[projectionsIn[V], dominatesQ[#, P] &], Tr]`. Given projection `P` in the ambient algebra and context `V`, returns the smallest projection in `V` dominating `P`. Then `daseinSubobject[P]` constructs the clopen subobject from pointwise `daseinO[V, P]`.

4. **Quantum context-category construction**: `cc_quantum` per §3.1.

5. **Classical control construction**: `cc_classical` per §3.2.

6. **Subobject enumeration** for both sides via the v2-style approach (direct construction is feasible at 8 contexts).

7. **Kernel candidate library**: §4.1–§4.6 and §4.8, computed for both sides.

8. **Comparison tabulation**: side-by-side four-cell counts for each kernel candidate across the two sides.

9. **Exhaustive sweep** (§4.7): all non-regular subobjects, four-cell counts on both sides, find divergence patterns if any.

10. **Summary**: positive / negative / mixed verdict per criteria in §5.

Output target: ~50–100 lines for the side-by-side report; structured tables, no enumeration of subobjects.

## 7. Scope and time estimate

Honest estimate: a few days of focused work, not a weekend. The conceptual setup (linear-algebraic projection arithmetic, daseinisation primitive, two parallel context-category constructions) is roughly 2× the code volume of v2-p3. The hard part is *interpretation* of the comparison tables, not the code itself.

Risks:
- The discretisation might be too coarse to surface a quantum signal even if one exists in full `Sub_cl(Σ_{M_2(C) ⊕ C})`. Mitigation: a negative v3 result is still informative — it tells us where the threshold is for the signal to appear (more contexts, more directions, less discretisation), and that's a finding worth recording.
- The script might find a quantum/classical divergence that's traceable to spectrum-size arithmetic rather than to daseinisation lifts. Mitigation: the §5 success criteria explicitly require the divergence to be traceable to §3.3 daseinisation calculations.
- The kernel candidates §4.1–§4.6 might all fail (regular kernels with cell-pattern indifference); §4.7 might find nothing in the discretisation. The result is negative, but the script architecture is reusable for finer discretisations (more directions, higher-dim summands), so the investment is not wasted.

## 8. What to do with results

**Positive result** (some kernel `a` shows cell-non-emptiness divergence between quantum and classical, traceable to non-commutativity):
- Update `physics-anchor/feasibility.md` to record the executed v3 checkpoint and identify the specific quantum-signal-bearing kernel `a`.
- Promote the physics anchor from "feasible at shape-driven level" (current status) to "feasible at non-commutativity-driven level."
- Open question becomes: does this kernel admit a Lean Layer-L theorem of the form "for `A = M_2(C) ⊕ C` discretised as `cc_quantum`, the four-position partition at kernel `a` is non-vacuous with cell-cardinalities `(I, R, E, D)`?" Probably tractable in Lean given the explicit projection arithmetic.

**Negative result** (no kernel shows cell-non-emptiness divergence):
- Update `physics-anchor/feasibility.md` to record the executed v3 checkpoint and the negative verdict.
- The physics anchor's structural claim retreats to: "the framework's partition machinery applies to topos-quantum-mechanics-relevant lattices at the shape-driven level, but the partition cells do not distinguish quantum from classical at the discretisation we tested." This is honest but weaker than the current "feasible" framing.
- The next research question becomes: do less coarse discretisations of `V(M_2(C))` (e.g. more directions, the continuum) surface a signal? This is research scope for a successor memo, possibly out of scope for FalseWork's first physics anchor.

### 10.4 Exhaustive sweep (Part 4): structurally null, cut-off accepted

The sweep produced the non-regular count `4129 of 4385` on both sides (94%) before being cut off mid-run during the all-4 count.

**The remainder of the sweep is structurally null** — it cannot detect non-commutativity by construction in v3 — so the cut-off is information-equivalent to a completion. Argument:

1. `Sub_cl(Σ_Q)` and `Sub_cl(Σ_C)` are isomorphic as bi-Heyting algebras. This follows from the §3.2 design choice: `V_d(C^7)` was constructed to be poset-iso to `V_d(M_2(C) ⊕ C)` with matching spectrum sizes and structurally matching restriction maps. Part 0 of the v3 run verified the data (`|Hasse| = 21 = 21`; `{1,2,2,2,2,3,3,3}` on both; `|Sub_cl| = 4385` on both).

2. The exhaustive-sweep question — "does kernel `a` admit an all-4-cell partition?" — is determined entirely by the lattice structure of `Sub_cl(Σ)`. Specifically:
   - `a ∈ Infrastructure(a)` automatically for non-bottom `a` (Infrastructure non-empty);
   - `¬¬a ∈ Exploitation(a)` automatically for non-regular `a` (Exploitation non-empty);
   - `Refusal(a)` non-empty iff `¬a ≠ ⊥`;
   - `Distribution(a)` non-empty iff `a ≠ ⊥` and `¬a ≠ ⊥` (typically `= |Sub_cl| − 1` for non-trivial kernels, dominated by the shared `V_0`-component).
   
   So all-4-cell ⇔ (`a` non-regular) ∧ (`a ≠ ⊥`) ∧ (`¬a ≠ ⊥`). All three predicates are intrinsic to the lattice.

3. Lattice-iso preserves intrinsic predicates. So the all-4-cell count is exactly equal between Q and C. The cell-non-emptiness verdict from the exhaustive sweep is structurally pinned to **match**.

4. The only place non-commutativity can enter the v3 partition is through kernels that *reference the daseinisation of a specific projection* — i.e., the named kernel candidates 4.1, 4.3, 4.5, 4.8 in Part 3, not the exhaustive sweep in Part 4. The exhaustive sweep iterates over the lattice; it never touches the daseinisation. Therefore it is blind to non-commutativity by construction.

This is itself a structural finding: **the v3 quantum-vs-classical signal can live only at named daseinisation-derived kernels, not at any lattice-internal kernel choice.** The §10.3 cell-cardinality result at candidates 4.1 and 4.3 is therefore *the* v3 signal; the exhaustive sweep was load-bearing only as an empirical sanity check, and we have enough lattice-structural argument to close it out without further computation.

If a future patch wants to empirically verify the structural argument (e.g., as a sanity check before committing to a v4 build on a different algebra), the streamlined O(`|Sub_cl|`) check `non-reg ∧ ¬a ≠ ⊥ ∧ a ≠ ⊥` would finish in seconds and produce the matching all-4 counts on both sides. The original Part 4 implementation (`fourCells` per kernel) is over-engineered — it computes Distribution and Infrastructure counts that we don't actually need for the non-emptiness verdict.

### 10.5 Verdict

**Cell-non-emptiness criterion: NEGATIVE on all named candidates (Part 3) and structurally null on the exhaustive sweep (Part 4).** No candidate in the named list (4.1, 4.2, 4.3, 4.5, 4.8) produces a non-emptiness divergence between quantum and classical; the exhaustive sweep is guaranteed by lattice-isomorphism to produce matching counts and therefore cannot contribute a divergence either. Matches §3.4 prediction.

**Cell-cardinality criterion: POSITIVE on candidates 4.1 and 4.3.** The cardinality ratios are clean (≈ 2^3 = 8 on Infrastructure, ≈ 0.25 = 1/4 on Refusal) and traceable to the §3.3 daseinisation-lift divergence at off-direction contexts. This is a *quantitative algebra-sensitive signal* — the framework's partition machinery is sensitive to non-commutativity at the cell-count level on tight (Heyting-regular) kernels.

**Overall**: **mixed result** per §5 criteria. The framework's machinery detects non-commutativity quantitatively but not categorically in this discretisation.

A bonus structural finding from §10.4: the *only* place a quantum-vs-classical signal can live in v3 is at kernels that reference the daseinisation of a specific projection. Lattice-internal kernel choices (the exhaustive sweep) are blind to non-commutativity by construction whenever the classical control is built poset-iso to the quantum side. This sharpens the scope of where to look for a categorical signal: either (a) a higher-dimensional algebra carrying Kochen-Specker (v4 on M_3(C); KS would block the poset-iso construction, breaking the lattice-iso premise), or (b) a different formulation of the kernel-choice question that doesn't pass through the Heyting-erasure for daseinisation-derived kernels.
