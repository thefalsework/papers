# Battery v5 — functional role: the knife that landed

**Question.** The confound a Debian person raises immediately: is the
Exploitation cell just the library/devel sections in costume? Roles that
exist to be depended upon accrete dependents; no battery generation had
ever seen functional role, because it is institutional metadata, not
graph structure. Control: **exact stratification** — a pair must agree
on kernel, exact distance, and archive Section, with the full v4
eight-feature caliper battery inside each stratum.

**Verdict: REVERSES — the Debian claim is dead.** Δ_ER = −0.076 on
79,822 same-section pairs (band ±0.012, pct 0.0, maxSMD 0.0095 — the
cleanest balance of any generation). Within role, Refusal out-grows
Exploitation. The descriptive D-over-E ordering also dissolved (NULL):
both axes were functional role in costume. Fourth in-house kill; the
certified-claims table is empty; record 10 for 28.

**The tell was in the blind pre-check.** Unlike momentum and the oracle
(both nearly balanced, both leaning *against* E), role was genuinely
imbalanced *with* the deflating story: E-members were 2.4× more
library-flavored than their R twins (13.1% vs 5.4% in
libs+libdevel+devel), and only 6% of v4 pairs agreed on section. The
first four batteries matched everything about a package except what kind
of thing it is.

**The anatomy (post-hoc, descriptive, unscored).** The within-role
reversal is heterogeneous: javascript −0.53 (11,109 pairs) and web −0.50
carry it; doc +0.015, java +0.67. Leave javascript out and the pooled
within-role estimate is −0.003 — zero. Precise obituary: the cross-role
claim was role composition (dead regardless of the decomposition); the
within-role effect is null-to-negative, its negative sign mostly Debian's
atypical javascript packaging. No reading of the data leaves a positive
effect anywhere.
